# Tutorial Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A guided replay of one real 3-player game where the new player places each tile on a ghost, every move is explained, plus a Practice entry in the `...` menu.

**Architecture:** The tutorial runs entirely in the browser. A committed script (`src/tutorial/script.ts`) holds the 17 recorded turns. A pure model (`src/tutorial/model.ts`) replays it with the shared engine to produce boards, standings, score breakdowns and placement feedback. A `Tutorial` screen feeds `Board`, `Rack` and `Scoreboard` from that model, reusing the game screen's drag-and-drop after it is lifted into a hook. A `tutorialSeen` flag on `users` drives a one-time popover.

**Tech Stack:** TypeScript, React 19, CSS modules with tokens from `src/index.css`, Convex, Vitest + Testing Library, `convex-test`.

**Spec:** `docs/superpowers/specs/2026-11-04-tutorial-design.md`

## Global Constraints

- TypeScript only. CSS modules only, colors and spacing from `src/index.css` tokens. No inline styles except the existing pointer-position pattern (`style={{ left, top }}`) used by the drag tile.
- The tutorial creates nothing in Convex and never touches stats.
- Opponent names: seat 0 is **Isolde**, seat 2 is **Rostam**. The player is seat 1, shown as "You".
- Every number on the coach card comes from `scoreTurn`; nothing typed by hand.
- No hard or triggering words in any coach text.
- Do not run `convex codegen` (it pushes to dev). If a new Convex module is added, hand-edit `convex/_generated/api.d.ts`. This plan adds no new module.
- Verify with `npm run typecheck`, `npm run lint`, and `npm test -- --no-file-parallelism`. Single files: `npx vitest run <path>`.
- Confirm the branch is `bhdoggett/tutorial` right before each commit.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Phones are portrait only. Light and dark themes both.

## Review Focus

1. **Ghost on an occupied square** (stacks: turns 11 and others). The ghost must show over the existing tile, and dropping the right tile there must stage it, not be refused. `place()` refuses a letter equal to the square's current letter, so check none of the player's stacks are same-letter (Task 2 test pins it).
2. **Two identical letters in one turn** (turn 2 has two Ns). Either N on either N ghost counts as right (Task 2 test).
3. **Blank tile.** Dropping the `?` on its ghost stages it with the ghost's letter and no letter picker. Dropping it on a non-ghost square stages it as a wrong tile with no picker (Task 6 test).
4. **Leaving mid-tutorial and coming back** starts at turn 1 with an empty board (Task 6 test).
5. **Popover stacking.** The tutorial popover never shows while the display-name, rule-change, game-over or friend-request popups are open, and never shows twice (Task 7 test).

- Produces: `export function Tutorial(props: { onLeave: () => void; onNewGame: () => void }): JSX.Element`. On mount calls `markTutorialStarted()` from `src/tutorial/seen.ts` (Task 7).

State machine (local `useState`, nothing persisted): `turn` (0–17) and `phase`:
- `"watch"` on an opponent turn: board shows `tilesAfter(turn + 1)` with that turn's cells in `recentCells` after a ~600ms pause; card shows `COACH[turn].after` + breakdown + Next → `turn + 1`.
- `"place"` on the player turn: board shows `tilesAfter(turn)`, `ghosts` = `SCRIPT[turn].placements`, rack `letters` = non-blank letters of that turn, `blanks` = blank count; `nameBlank(x, y)` returns the ghost's letter if a blank ghost is at (x,y); otherwise it returns the letter of the first blank ghost, so a misplaced blank stages as a wrong tile and the letter picker never opens. Card shows `COACH[turn].before`. Play button always enabled-looking only when `checkPlacement` is `ready`; pressing it otherwise sets card to error with `describeFeedback`, and `badCells` = the offending cell.
- `"played"` after a correct Play: board `tilesAfter(turn + 1)`, `newSquares` highlighted via `goodCells`, card shows "Nice: +{score}" + `COACH[turn].after` + breakdown + Next.
